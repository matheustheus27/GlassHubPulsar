# CV & Cover Letter Project Guidelines

* **Tailwind & Print Styles:** Always include print-specific utility classes (`@media print` or `print:*`) when modifying layout or preview components to ensure visual consistency between UI preview and generated PDFs.
* **Dual Document Support:** Ensure any layout or UI updates account for both **Resume (CV)** and **Cover Letter** document types and their respective schemas.
* **Text Formatting & Custom Tags:** Always process rich text strings through `processInHtml()` from `tagProcessorService.ts` before rendering (to support `<BOLD>`, `<ITALIC>`, `<UNDERLINE>`, `<HIGHLIGHT>`, and `<STRIKETHROUGH>`). This applies to both template inputs and AI-generated chat responses. Never inject raw HTML directly into component templates without tag sanitization/parsing.
* **AI Integration & Local Engine:** Interactions with the local LLM (Ollama) must be handled asynchronously via dedicated backend routes (`/ai/messages`) and frontend services (`aiService.ts` / `aiChatService.ts`). Always send the complete conversation history to maintain context continuity.
* **Custom Hooks & State Persistence:** Isolate UI state, theme preferences, and chat history into reusable custom hooks (e.g., `usePreferences.ts`, `useChatStorage.ts`). Ensure state initialization reads synchronously from `localStorage` to prevent UI flicker and proper `JSON.parse`/`JSON.stringify` serialization for complex structures.
* **Service Decoupling:** Keep HTTP API logic (such as PDF exporting and AI chat endpoints) isolated in service files inside `src/app/services/` (e.g., `exportService.ts`, `aiChatService.ts`) rather than embedding raw `fetch` calls directly inside React page components.
* **Component Splitting & Data Abstraction:** Keep data structures isolated in structural files within `src/app/data/` (e.g., `PersonalData.ts`, `ProjectData.ts`, `CoverLetterData.ts`) and delegate pure rendering to UI components.
* **Internationalization (i18n):** Never hardcode text strings inside React components. Always retrieve strings dynamically using translation dictionary keys (`TranslationsData.ts`) and pass the active locale to AI prompts to ensure responses match the selected UI language.
* **Docker Workspace Context:** The project isolates the client interface inside `/frontend`, the PDF engine inside `/backend`, and the AI engine inside `/ollama`. Ensure network endpoints, file paths, container aliases, and Docker volume mounts (`ollama_data`) remain aligned across services.
* **User Feedback & State:** Always handle API execution states (PDF export, AI processing) asynchronously, providing real-time feedback notifications or loading indicators to the end user.
